# RC278 — فلاتر المطابقة التامة الموقعة للقوائم المرقمة

**المنفّذ:** توسيع مولّد Flutter للقوائم `*.list.paginated`، ليعرض ويرسل فلاتر مطابقة تامة للنصوص والقيم المنطقية مع البحث الشامل وInfinite Scroll.

## مصدر الثقة

لا يعرض المولّد أي فلتر إلا إذا تطابق اسم المعامل ونوعه وقيوده في **طلب Backend Fable الموقّع** وOpenAPI، وظهر الحقل نفسه بنوع مطابق في نموذج عناصر الاستجابة الموقّع. يستبعد الحقول المحمية/الحساسة، وأسماء أسرار الهوية والرموز، ومعاملات `page`/`limit`/`mode`/`q`/`locale`/`sort`. يقتصر إنشاء الواجهة العامة على **أول ثلاثة حقول مطابقة آمنة** من العقد؛ لا يدّعي شمول كل الفلاتر المتاحة في النظام.

المدعوم حاليًا:

- `string/text`: فلتر مساواة نصي اختياري بحد أقصى 191 حرفًا، لا يُرسل إذا تُرك فارغًا.
- `boolean`: اختيار «Any / True / False»، ويرسل فقط `true` أو `false` عندما يكون `enum` موقّعًا بهذه القيم.
- يمكن استخدام الفلاتر مع `q` الشامل: جميع الصفحات تُطلب من Backend بالمرشّح نفسه؛ لا يتم ترشيح العناصر التي وصلت للهاتف محليًا فقط.

## سلسلة التكامل

`Signed Fable Contract + OpenAPI → Planner → Domain Port → Repository Adapter → UseCase → Controller → Infinite-scroll UI`.

تتلقى طبقة Data فقط معاملات `query`، وتتحقق من النصوص والقيم المنطقية. يحتفظ Controller بلقطة للفلاتر مع حالة البحث لكل طلب؛ عند تغيير الفلتر تبدأ الصفحة الأولى، وتُرفض النتائج المتأخرة بعد تبديل الهوية/البحث. كما تُمسح مدخلات الفلترة عند تغيّر Gateway أو الهوية.

## خارج نطاق RC278

الفرز غير مدعوم تلقائيًا لأن عقد `sort` الحالي لا يعلن **قائمة حقول الفرز المسموحة**؛ إرسال اسم حقل بالتخمين لا يضمن مطابقته لسياسات Backend. كما أن الفلاتر الرقمية والنطاقات الزمنية، وسياق Tenant المُدار، والتعديل والحذف المشروطين، تتطلب ربطًا وتحققًا متخصصين.
