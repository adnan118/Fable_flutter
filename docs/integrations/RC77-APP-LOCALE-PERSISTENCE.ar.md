# RC77 — حفظ لغة واجهة Flutter

## العقد الصحيح
- قرار لغة الواجهة ملك للتطبيق نفسه، مستقل عن نوع Backend (`fable` أو `other`). لا يُشتق من وجود `languages.list` أو Google Translate، ولا يُسمح بإرسال أسرار الترجمة إلى Flutter.
- يحدد `lib/src/generated/language_policy.dart` اللغات المسموحة في التطبيق المولد. **لا يجوز** تحويل كل لغة يرد بها Backend إلى ARB موجودة دون دعم فعلي.
- `FableLocalePreferenceStore` في Core يحفظ التفضيل المعتمد في تخزين النظام الآمن، ويقرأه عند إعادة تشغيل التطبيق. اختيار «لغة الجهاز» يمسح التفضيل.
- عند ترقية التطبيق وحذف لغة كانت مسموحة سابقاً، لا تُفرض لغة غير مدعومة؛ يعود التطبيق إلى اختيار النظام.
- يحفظ التطبيق الخيارات بالتسلسل لتفادي استبدال اختيار جديد بعملية حفظ قديمة بطيئة، ولا يغيّر اللغة المرئية إن فشل حفظ اختيار المستخدم.

## النطاق والأمان
- لا تتغير عمليات Auth أو FCM أو صلاحيات Backend عند تغيير اللغة؛ تفضيل الواجهة ليس صلاحية.
- هذه الدفعة لا تدّعي أن جميع النصوص الديناميكية جرى ترجمتها. `languages.clientCopy` تحديث اختياري لنصوص منشورة، و`AppLocalizations` يبقى fallback معتمد.
- لا يتم إرسال كلمة مرور أو طلب من API لحفظ اللغة، ولا إضافة مسارات Fable لباك آخر.
- الاختبارات الآلية تثبت صلاحية التفضيل وإعادة القراءة/إزالة القيمة والتعامل مع لغة قديمة/فشل التخزين. الاختبارات الأصلية على أجهزة Android/iOS لازمة لمراجعة سلوك Keychain وKeystore بعد إعادة التثبيت والترقية.

## إغلاق ميزة Localization بالكامل لاحقاً
تحتاج الميزة إلى ربط نسخ `clientCopy` مع كامل شاشات المشروع، تفريغ/إعادة ترجمة النصوص الديناميكية من Backend، خيارات تغيير اللغة، اتجاه RTL، ودعم تخزين المؤقت والتحديث بلا اتصال وتبديل المستخدم والتحقق من البيانات المترجمة. لا تعلن `Localization` كاملة بالاعتماد على RC77 وحده.
