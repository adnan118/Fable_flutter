# RC72–RC73 — نشر سياسة الخصوصية وربط المحتوى والإشعارات

## المصدر وما تم تطويره
- **Backend Fable RC66:** `content-pages` ميزة اختيارية. العمليات المصدّرة فقط عند التفعيل:
  - `content.page.read` → `GET /content/pages/{slug}` (منشور وساري المفعول).
  - `content.page.accept` → `POST /content/pages/{pageId}/accept` للمستخدم المصرح، مع `versionId`.
  - `content.publicChanges` → `GET /content/pages/changes` يعيد snapshot كاملاً بالـslugs والنسخ الحالية.
- **RC72 Flutter:** شاشة الصفحة المنشورة تعيد قراءة النسخة عند استئناف التطبيق وإشارات تغيير محتوى موثوقة اختيارية. إذا تغير `versionId` تُعرض النسخة الجديدة ويزول قبول النسخة السابقة. وعند تغير هوية المستخدم من Stream معتمد تزول الموافقة المحلية. عند فشل جلب أحدث نسخة لا يسمح زر الموافقة باستخدام كاش قديم.
- **RC73 Flutter:** تستبدل شاشة `content` التعريفية بدليل الصفحات المنشورة الفعلي، بشرط تطابق طرق ومسارات ومصادقة العمليات الثلاث أعلاه مع عقد Fable المستورد، وتوفر `FABLE_API_BASE_URL`؛ تُستخدم الـslugs المعادة من الباك فقط دون اختلاق أسماء أو مسارات.
- **Notifications:** عند تمييز حدث `PRIVACY_POLICY_UPDATED` عبر `noticeId` المطابق لإشعار Fable ومعرفَي الصفحة والنسخة الموثقين، يقدّم Inbox فتح شاشة المحتوى فقط عندما تتوفر قدراتها في العقد. لا يُستخدم URL من Payload ولا يُفعل المسار لباك آخر.
- تقبل واجهة القراءة الـslugs الآمنة العربية واللاتينية حتى طول 190 المسموح في DTO الباك، دون علامات تقسيم المسار أو معاملات URL.

## الفصل بين نوعَي Backend
- `other` لا يُمرر تلقائياً عمليات Fable أو أسماء Headers أو مفاتيح Auth الخاصة به. يمكنه استعمال Widgets العامة عند استيراد Operation IDs وDecoder ملائمين صراحةً. ولا يظهر Content Index التلقائي الخاص بـFable لباك غير Fable.
- لا تُظهر الواجهة محتوى Draft أو Scheduled-future؛ Backend هو المسؤول عن فلترة النسخ السارية المفعول، وواجهة Flutter تتعامل مع snapshot منشور فقط.

## الحدود التي لا يجوز تحويلها إلى PASS
- نجاح CI ليس دليلاً على تشغيل خادم مولّد مع قاعدة بيانات، أو حفظ الموافقة فعلياً للمستخدم، أو إرسال FCM على أجهزة. كل هذه **تحتاج E2E**.
- لا توجد آلية من Backend في العقد الحالي لقراءة حالة الموافقة المسجلة لهذا المستخدم؛ لذلك `_accepted` مؤشر جلسة UI مؤقت وليس شهادة قانونية دائمة، والخادم يتحكم بتسجيل قبول نسخة محددة.
- `refreshSignals` و`identitySignals` مداخل اختيارية لمشروع التطبيق؛ إشارة Firebase عند وصول Push ليست ضماناً لتسليم كل حدث. إعادة التحميل عند Resume والتحديث اليدوي هي مسارات التعافي.
- Backend دعوة تحديث سياسة الخصوصية عند نشر إصدار بدلاً من المسودة، واحترام `effectiveFrom` يحتاجان اختباراً حياً قبل Production.
