# RC144 — واجهة دعم فنية بعقد Backend موثّق (Stage 4)

أُضيفت `FableSupportWorkflowPage` بوصفها مكوّنًا وظيفيًا فعليًا لإنشاء تذاكر الدعم وعرض حالتها، **وليست شاشة دعم مفعلة تلقائيًا**.

## الإعداد الصحيح
يتولى مطوّر المشروع إنشاء `FableSupportRepository` فقط بعد:
1. استيراد عقد API خاص بمشروع Fable أو Backend آخر، ثم تحديد عمليتي `list` و`create` الموجودتين فعليًا في العقد عبر `FableSupportOperations.fromContract`. Fable RC66 لا يضمن وجود Support API افتراضي.
2. ربط `BackendApiGateway` الذي يمتلك جلسة المستخدم وحدها. لا تضع أسرار مزوّد أو Webhook مستقبِل في العميل.
3. توفير `FableSupportListDecoder` مطابق **لبنية جواب الخادم الحقيقية**، و`FableSupportRequestEncoder` مطابق لطلبه. لا يفترض المكوّن أسماء حقول JSON المجهولة.
4. حقن `identityRevision` و`identityInvalidations` و`isAuthenticated` من **نفس جلسة Backend المختارة**. لا تعر هويات Fable إلى Other.
5. عرض المكوّن ضمن تكامل مشروع مُعتمد؛ `supportFeature` لا يزال لا يتجاوز فحص `canLaunchFable` الافتراضي أو `externalScreen` دون Adapter حقيقي.

## سياسة الأمان وتجربة المستخدم
- لا يوجد طلب تلقائي فور فتح الصفحة. التحميل والإنشاء بإجراء صريح من المستخدم.
- تُمحى البيانات الخاصة والحقول فور تبديل الهوية أو إبطالها.
- أي رد من هوية قديمة يُرفض ولا يستعيد قائمة التذاكر.
- العملية الكتابية لا تعيد الإرسال تلقائيًا؛ عند انقطاع الشبكة يُعرض تحذير أن حالة الإرسال **غير مؤكدة**، ويجب مراجعة التذاكر أولًا.
- النجاح يفرغ الحقول ويجبر إعادة تحميل القائمة من Backend الموثّق.
- التحقق من مدخلات المستخدم موجود في الصفحة وفي Repository. ويجب على Backend تكراره مع authorization/rate limit/audit.

## التغطية والأعمال المتبقية
- خمسة اختبارات Widget لعدم المصادقة، القراءة اليدوية، تبديل الحساب أثناء رد مؤخر، الإنشاء، وحالة الطلب غير المؤكدة.
- Node gate يؤكد عدم اختراع مسارات وعدم تفعيل Support تلقائيًا.
- **لم نختبر Backend حيًا.** ينبغي توفير عقد وتفاصيل provider فعلية، واختبارات سجل التذاكر والتزامن والصلاحيات.
- ترجمة نصوص الصفحة وربطها بمكتبة RTL والتصميم الكامل تبقى ضمن مراجعة تطبيق المشروع عند استخدامه.

المرحلة الرابعة لا تزال مفتوحة: [RC141 Issue #74](https://github.com/adnan118/Fable_flutter/issues/74).
