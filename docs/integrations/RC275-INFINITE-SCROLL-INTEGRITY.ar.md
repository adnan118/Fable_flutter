# RC275 — متانة Infinite Scroll تحت نتائج البحث الكبيرة

تتمة لـ Backend RC274 وFlutter RC273. مصدر التغييرات يقتصر على مولّد الصفحات المرقّمة في `tools/render-typed-feature-rc116.mjs`، ولا يغيّر عقد Backend أو API أو تفاصيل التوقيع.

## إصلاح عرض النتائج

- كانت `items` تُعاد في كل قراءة بواسطة `List.unmodifiable(_items)`، مما ينشئ نسخة كاملة من النتائج المخزنة لدى Controller في كل إعادة رسم. يستخدم التنفيذ الجديد `UnmodifiableListView` بواجهة قراءة فقط دون نسخ جميع السجلات مرارًا.
- في السابق، إذا أرسل الخادم صفحة فارغة رغم وجود `totalPages` لاحقة، كان Controller يقرر أن القائمة انتهت، فتختفي باقي نتائج البحث من دون إشارة واضحة. الآن يُعدّ ذلك **استجابة غير متسقة** ويُظهر رسالة فشل وإعادة محاولة للصفحة نفسها بدل إسقاط النتائج المتبقية.
- تبقى العناصر المحملة سليمة حين تفشل الصفحة التالية. إعادة المحاولة لا تعيد إرسال جميع الصفحات، ولا تُفعل تلقائيًا بلا قرار المستخدم.
- عند تبديل الحساب أو عبارة البحث، يبقى فصل النتائج القديمة عن الجديدة قائمًا باستخدام Request Epoch/Session identity.

أضفت Widget test مولّدًا يحاكي الصفحة الفارغة غير المتوقعة، واختبارات Node مصدرية تؤكد عدم نسخ العناصر مع كل إعادة رسم، ووجود حالة إعادة المحاولة، والتوافق مع العقد القديم الذي لا يدعم search pagination.

**المراجعة:** 18/18 اختبارًا مصدريًا معزولًا عبر JavaScript، يتضمن فحوص RC267–273 وRC275. لم تُشغّل اختبارات Flutter SDK أو Backend+MySQL على بيئة حقيقية؛ قرار الإنتاج يبقى **NO_GO**.

## القيود المتبقية

- Offset pagination قد يعرض تكرارًا/إزاحةً أثناء إدخال سجلات أو حذفها بالتزامن؛ لتحقيق ثبات كامل أثناء تغيّر البيانات نحتاج لاحقًا Cursor Pagination أو Snapshot token من Backend.
- الحصول على لقطة مصدر ZIP لا يعني نجاح Build أو أداء على الأجهزة. W5/W6 ووحدات PATCH/DELETE والأمن والاختبار العملي تظل ضمن الخطة المفتوحة.
